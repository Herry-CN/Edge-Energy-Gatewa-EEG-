# Modbus 设备模型规范 V1.1

### 1. 文档定位

本文件是 EEG 项目中设备数据模型的唯一准确来源。

约束如下：

- 设备字段命名、寄存器地址、倍率、枚举值，以本文件为准。
- `MQTT 网关通信协议 V1.1.md` 与 `STM32 软件架构设计 V1.1.md` 只能引用本文件，不得另行定义冲突字段。
- V1 版本当前只正式定义 `Charger` 设备模型；`battery`、`inverter`、`meter`、`sensor` 只保留 Topic 位置，待后续新增设备模型文档后再启用。

### 2. Modbus 地址基准规则

结合现场 `mbserver` 验证，V1 统一规定如下：

| 名称 | 示例 | 说明 |
| ---- | ---- | ---- |
| 完整显示地址 | `401001` | 带固定前缀 `400001` 的保持寄存器显示地址 |
| 文档简写地址 | `1002` | 本项目文档中统一使用的 1-based 地址写法，等价于 `401001` 去掉前缀后的编号 |
| PDU 原生地址 | `1001` | 真正进入 Modbus RTU 报文的零基地址 |

换算关系：

```Plain Text
完整显示地址 = 400001 + PDU原生地址
文档简写地址 = PDU原生地址 + 1
PDU原生地址 = 文档简写地址 - 1
```

统一要求：

- 本文寄存器表保留当前项目已投入使用的“文档简写地址”写法，如 `1002`、`1050`。
- STM32 与任何实际 Modbus RTU 报文交互时，统一使用 `PDU 原生地址`。
- 若上位机工具使用 `4xxxxxx` 地址风格，直接输入完整显示地址，如 `401001`。
- 若上位机工具使用 “PLC 地址 / 1-based / 文档地址” 风格，直接输入文档简写地址，如 `1002`。
- 若驱动接口直接收 Modbus PDU 地址，则必须传 `1001`，不能传 `1002`。

默认功能码：

- 读保持寄存器：`0x03`
- 写单个保持寄存器：`0x06`

### 4. Charger 寄存器映射

说明：

- 表中“文档简写地址”是项目文档统一写法。
- 表中“PDU 原生地址”才是 RTU 报文里真正发送的地址。
- 本版地址已按现场 `mbserver` 数据逐项校准，其中 `start_stop` 位于 `401035`，`start_stop_control` 位于 `401051`。
- V1 统一按 `16 bit 单寄存器` 定义；若后续接入新厂家设备需要 `uint32`、`float` 或跨寄存器字序，必须先修订本文件，再允许修改协议层。

| 模型字段 | 文档简写地址 | 完整显示地址 | PDU 原生地址 | 寄存器名称 | R/W | 单位 | 编码/取值 | 说明 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| state | 1002 | 401002 | 1001 | 桩状态 | R | / | `0: 桩正常` `1: 桩故障` `2: 桩报警` | 原始状态码 |
| fault_code | 1003 | 401003 | 1002 | 桩故障码 | R | / | `uint16` | `0` 表示无故障 |
| enable | 1024 | 401024 | 1023 | 充放电使能 | R/W | / | 建议 `0: 禁止` `1: 允许` | 厂家如有不同，以设备协议为准，但 MQTT 命名不变 |
| charge_power_setpoint | 1025 | 401025 | 1024 | 充电输出功率设定值 | R/W | 0.1kW | `uint16` | 供 `set_charge_power` 命令使用 |

### 5. 字段解释与派生规则

为避免 MQTT 层和业务层再次解释不一致，V1 增加以下派生约束：

- `state` 是原始寄存器字段，只表示 `正常/故障/报警`。
- 若业务层需要表达 `idle`、`charging`、`offline` 等运行态，应在上层协议中使用派生字段，不得反向修改本表中的 `state` 定义。
- `mode` 是原始寄存器字段，只表示 `CHG/V2G` 模式。
- `temperature` 上报到上层前必须先做 `-40` 偏移还原。
- `energy_charge` 与 `energy_discharge` 在 V1 均视为单寄存器累计量；如果后续项目确认厂家协议为双寄存器累计量，必须先更新本文件版本号。

### 6. 轮询策略

### 6.1 总体原则

- RS485 总线采用“单帧调度”策略：每个调度周期最多发送 1 帧 Modbus 请求，避免阻塞 ESP8266 的 AT 收发。
- 在线状态下以 `300 ms` 作为最小调度粒度。
- 控制类数据优先级高于测量类，测量类高于累计量。
- 写命令成功后，不等待下一个完整轮询周期，需在 `300 ms` 内触发一次回读校验。

### 6.2 分级实时性策略

| 等级 | 字段 | 推荐周期 | 业务目标 |
| ---- | ---- | ---- | ---- |
| A：安全/控制类 | `state` `fault_code` `enable` `mode` `start_stop` | `300 ms ~ 500 ms` | 保障启停、故障、模式切换可快速可见 |
| B：运行电参类 | `voltage` `current` `power` `soc` `temperature` | `1000 ms`（运行中） / `3000 ms`（空闲） | 兼顾实时监测与总线占用 |
| C：累计量类 | `energy_charge` `energy_discharge` | `5000 ms` | 累计量变化慢，无需高频刷新 |

### 6.3 推荐读块划分

为兼顾协议清晰度与工程可实现性，推荐如下读块：

| 读块 | 文档简写地址 | PDU 原生地址 | 数量 | 包含字段 |
| ---- | ---- | ---- | ---- | ---- |
| Block-A1 | `1002` | `1001` | `2` | `state` `fault_code` |
| Block-A2 | `1024` | `1023` | `2` | `enable` `charge_power_setpoint` |
| Block-B1 | `1029` | `1028` | `4` | `voltage` `current` `power` `soc` |
| Block-A3 | `1035` | `1034` | `1` | `start_stop` |
| Block-C1 | `1036` | `1035` | `1` | `energy_charge` |
| Block-C2 | `1038` | `1037` | `1` | `energy_discharge` |
| Block-B2 | `1040` | `1039` | `1` | `temperature` |
| Block-A4 | `1050` | `1049` | `2` | `mode` `start_stop_control` |

### 6.4 推荐调度规则

在线状态：

- 每 `300 ms` 从到期任务队列中取 1 个最高优先级读块发送。
- `A` 级读块优先保证周期；
- `B` 级读块其次；
- `C` 级读块最后。
- 同一优先级下多个读块必须轮询执行，不能长期固定优先 `Block-A1`，否则会导致电参和温度长期不刷新。

离线判定：

- 连续 `3` 次访问失败，设备转为 `offline`。
- `offline` 后降级为每 `3000 ms` 仅探测 `Block-A1`。
- 连续 `2` 次探测成功后恢复在线轮询。

写命令校验：

- `start_stop_control`、`enable`、`charge_power_setpoint` 写成功后，在 `300 ms` 内优先补一次对应读块回读。
- 命令 ACK 只能在写操作结果明确后发送；状态上报则由后续轮询或立即回读结果驱动。

### 7. 与上层协议的一致性要求

- MQTT 状态上报中的 `fault_code`、`enable`、`energy_charge`、`energy_discharge`、`mode`、`start_stop`、`start_stop_control` 均必须来源于本文件。
- MQTT 若保留已有字符串字段（如 `state`、`mode`），应增加相应原始码字段，避免丢失寄存器真值。
- STM32 寄存器缓存层必须同时保存“原始寄存器值”和“派生业务状态”，不得只保留派生结果。

以后换品牌充电桩，只需要先在本文件中完成新寄存器映射，再同步更新驱动实现。
