# ESP8266 MQTT-AT 固件烧录方案分析报告

## 一、硬件实际情况（与方案原文的关键差异）

### 1.1 板载 ESP8266-12F，不是 ESP-01S 模块

从《野火 STM32F103 霸道 V2 开发板硬件规格书》确认：

> "霸道 V2 板载有 ESP8266 芯片和 1MB Flash（大尺寸的连云固件烧不了）。"

> "WIFI 底板有 ESP8266WIFI 模块，FLASH 1MB-串口接口"

**方案原文中反复提到的"ESP-01S"是错误的。** 实际硬件是板载 ESP8266-12F 芯片（直接焊在开发板上），1MB Flash 容量正确，但模块形态完全不同。

### 1.2 引脚连接关系（来自项目 Doc/readme.txt）

| ESP8266-12F 引脚 | 连接到 | 说明 |
|---|---|---|
| VDD | 5V | 供电 |
| GND | GND | 地 |
| TXD | PB11 (USART3_RX) | ESP8266 发 → STM32 收 |
| RXD | PB10 (USART3_TX) | STM32 发 → ESP8266 收 |
| RST | PG14 | 复位控制（STM32 驱动） |
| IO (GPIO0) | 3V3 | **正常启动：接 3V3（高电平）** |

CH340 USB 转串口：
- CH340 RXD ↔ USART1 TX (PA9)
- CH340 TXD ↔ USART1 RX (PA10)
- 默认通过跳帽连接

### 1.3 板载专用固件更新引脚

硬件规格书原文：
> "ESP8266 正上方的四个引脚可用来更新 WIFI 固件"

这 4 个引脚是专门为 ESP8266 固件烧录设计的，不需要拆模块。

## 二、方案原文逐条分析

### A.1 下载两个东西

#### ① Flash Download Tool
**判定：正确，需要下载。**
- 官网地址正确
- 操作系统为 Windows，适用

#### ② ESP8266 MQTT-AT 固件
**判定：不需要下载！项目已自带固件。**

项目目录 `D:\modulebusLinkMQTT\Doc\` 下已有：
- `ESP8266_AT_MQTT_1M.bin`（1048576 字节 = 恰好 1MB，即 8Mbit）
- 这就是适用于 1MB Flash 的 MQTT AT 固件，烧录地址 0x00000

**方案原文中"去乐鑫官网下载 ESP8266 NonOS AT Bin V2.2.1"的步骤可以跳过。**

> 注意：方案原文提到的"ESP-01S 是 1MB Flash"中 Flash 大小正确，但模块型号错误。实际是板载 ESP8266-12F。

---

### A.2 让 ESP8266 进入下载模式

#### 原文描述的 ESP-01S 引脚图
**判定：不适用。** 板载 ESP8266-12F 没有 2x4 邮票孔排列，GPIO0 通过板载跳帽连接到 3V3。

#### GPIO0 拉低 = 下载模式
**判定：原理正确。** ESP8266 的下载模式触发条件确实是 GPIO0 在上电/复位时为低电平。

霸道 V2 板上的操作方式：
1. 找到 ESP8266 旁边标有 "IO" 或 "GPIO0" 的跳帽（正常接 3V3）
2. 拔掉这个跳帽
3. 用杜邦线将 IO(GPIO0) 接到 GND
4. 按一下开发板复位键（RST）
5. 此时 ESP8266 进入下载模式

#### "STM32 要让出 USART3" 的建议
**判定：正确且关键。** 但解决方案有三种，原文只提到了两种。

## 三、三种烧录方案对比与选择

### 方案 A：外接 USB-TTL 小板（原文推荐）

**数据路径：** PC → USB-TTL 小板 → ESP8266 烧录引脚

**操作：**
1. 拔掉 ESP8266 ↔ USART3 (PB10/PB11) 的跳帽，防止 STM32 干扰
2. USB-TTL 的 TX → ESP8266 RX (W_RX)
3. USB-TTL 的 RX → ESP8266 TX (W_TX)
4. USB-TTL 的 GND → 开发板 GND
5. GPIO0 接 GND
6. 给 ESP8266 上电/复位
7. Flash Download Tool 选 USB-TTL 的 COM 口

**优点：** 最可靠，完全绕开 STM32
**缺点：** 需要额外购买 USB-TTL 小板（CH340/CP2102/PL2303 均可）

---

### 方案 B：STM32 透传桥（推荐，程序已写好）

**数据路径：** PC → CH340 → USART1 → STM32 中断转发 → USART3 → ESP8266

**项目已自带桥接程序：**
- `User/main_bridge.c`（替换 main.c）
- `User/stm32f1xx_it_bridge.c`（替换 stm32f1xx_it.c）

桥接程序的工作原理：
- USART1 收到字节 → 中断中立即写入 USART3（PC → ESP8266）
- USART3 收到字节 → 中断中立即写入 USART1（ESP8266 → PC）
- 自动控制 CH_PD（PG13）使能 ESP8266
- 自动控制 RST（PG14）复位 ESP8266
- LED1 常亮 = 桥接模式就绪

**优点：**
- 不需要额外硬件
- 桥接程序已经写好，直接用
- 利用板载 CH340，COM 口就是平时调试用的那个

**缺点：**
- 需要先刷桥接固件到 STM32，烧完 ESP8266 后再换回主程序
- 中断转发理论上有微小延迟，但 115200 波特率下完全够用

**详细步骤见下方第四节。**

---

### 方案 C：CH340 直连 ESP8266（跳帽重接）

**数据路径：** PC → CH340 →（杜邦线直连）→ ESP8266

**操作：**
1. 拔掉 CH340 ↔ USART1 (PA9/PA10) 的跳帽
2. 拔掉 ESP8266 ↔ USART3 (PB10/PB11) 的跳帽
3. 用杜邦线连接：CH340 TX → ESP8266 RX (W_RX)
4. 用杜邦线连接：CH340 RX → ESP8266 TX (W_TX)
5. GPIO0 接 GND
6. 复位
7. Flash Download Tool 选 CH340 的 COM 口

**优点：** 不需要额外硬件，不需要改 STM32 固件
**缺点：** 需要拔多组跳帽，操作步骤多，容易接错

---

### 方案选择建议

| 条件 | 推荐方案 |
|---|---|
| 手边有 USB-TTL 小板 | 方案 A（最省心） |
| 没有 USB-TTL，但会 Keil 编译下载 | **方案 B（推荐）** |
| 不想改代码，但会操作跳帽 | 方案 C |

---

## 四、方案 B 详细操作步骤（推荐）

### Step 1：准备工具

1. 下载 Flash Download Tool：https://www.espressif.com.cn/zh-hans/support/download/other-tools
   - 找「Flash Download Tools (ESP8266 & ESP32 & ESP32-S2)」→ 下载 zip → 解压
2. 固件已就绪：`D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin`（1MB）

### Step 2：切换桥接固件源文件

在 Keil 工程中（或文件操作层面）：
1. 将 `User/main.c` 重命名为 `main_backup.c`（备份）
2. 将 `User/main_bridge.c` 复制为 `User/main.c`
3. 将 `User/stm32f1xx_it.c` 重命名为 `stm32f1xx_it_backup.c`（备份）
4. 将 `User/stm32f1xx_it_bridge.c` 复制为 `User/stm32f1xx_it.c`

### Step 3：编译并下载桥接程序到 STM32

1. Keil 打开工程 `Project/Fire_F103ZE.uvprojx`
2. Build（F7）编译，确认无错误
3. 用 ST-Link / J-Link / FlyMcu（ISP下载）将固件下载到 STM32
4. STM32 运行后：LED1 常亮 = 桥接模式就绪

### Step 4：ESP8266 进入下载模式

1. 找到 ESP8266 旁边标有 "IO" / "GPIO0" 的跳帽位置
2. 拔掉 IO ↔ 3V3 的跳帽
3. 用一根杜邦线：一头接 IO(GPIO0)，另一头接 GND
4. 按一下开发板的复位键（RST）
5. 此时 ESP8266 已进入下载模式

### Step 5：打开 Flash Download Tool

1. 运行 `flash_download_tool_x.x.x.exe`
2. 弹框选择：
   - ChipType：ESP8266
   - WorkMode：Develop
   - LoadMode：UART
   - 点 OK

### Step 6：配置并烧录

主界面 SPI Download 标签页：
- COM：选 CH340 对应的 COM 口（设备管理器查看，就是平时调试用的口）
- BAUD：115200
- SPI SPEED：40MHz
- SPI MODE：DIO
- FLASH SIZE：8Mbit（1MB）

固件文件：
- 勾选第一行，点浏览选择 `D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin`
- 地址填：`0x00000`
- 勾选 DoNotChgBin

点 START → 进度条 0%→100% → 状态 SYNC → DOWNLOAD → FINISH（绿色）

**如果一直停在 SYNC：** GPIO0 没有成功拉低，重新执行 Step 4。

### Step 7：烧录完成，恢复 GPIO0

1. 看到 FINISH 绿色 = 烧录成功
2. 拔掉 IO ↔ GND 的杜邦线
3. 接回 IO ↔ 3V3 的跳帽（恢复正常启动模式）
4. 按一下复位键，ESP8266 正常启动

### Step 8：恢复主程序

1. 将 `main_backup.c` 恢复为 `main.c`
2. 将 `stm32f1xx_it_backup.c` 恢复为 `stm32f1xx_it.c`
3. Keil 重新编译并下载到 STM32
4. MQTT 应用程序正常运行

## 五、方案有效性总结

| 方案原文条目 | 判定 | 说明 |
|---|---|---|
| A.1 ① 下载 Flash Download Tool | 有效 | 正确，需要执行 |
| A.1 ② 下载 ESP8266 MQTT-AT 固件 | **可跳过** | 项目 Doc/ 下已有 ESP8266_AT_MQTT_1M.bin |
| A.1 提到 "ESP-01S" | **错误** | 实际是板载 ESP8266-12F，不是 ESP-01S 模块 |
| A.2 GPIO0 拉低进下载模式 | 有效 | 原理正确，但操作方式不同（用跳帽不是杜邦线找第3针） |
| A.2 STM32 让出 USART3 | 有效 | 正确，三种方案都可解决此问题 |
| A.2 建议用 USB-TTL 小板 | 有效但非唯一 | 方案 A 可行，但方案 B（透传桥）更方便 |
| A.2 "我给你写一个 STM32 透传桥" | **已写好** | main_bridge.c + stm32f1xx_it_bridge.c 已在项目中 |
| A.3 Flash Download Tool 设置 | 基本正确 | 参数全部正确，固件文件改用项目自带的 bin |
| A.3 COM 口选择 | 需修正 | 方案 B/C 用 CH340 的口，方案 A 用 USB-TTL 的口 |

**总判定：方案整体思路有效，但需要根据实际硬件（板载 ESP8266-12F 而非 ESP-01S）修正操作细节，且固件不需要额外下载。**
