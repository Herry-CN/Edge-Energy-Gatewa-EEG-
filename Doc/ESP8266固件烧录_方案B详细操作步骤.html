ESP8266 固件烧录 · 方案B 详细操作步骤

使用板载 CH340 + STM32 透传桥程序，无需 USB-TTL 小板

开发板：野火霸道 V2 · ESP8266-12F · 1MB Flash 固件：ESP8266_AT_MQTT_1M.bin

方案概述

  • 原理：STM32 运行透传桥程序，把电脑通过板载 CH340（USART1）发来的数据转发给 ESP8266（USART3）
  • 透传桥程序会自动拉高 PG13(EN) 使能 ESP8266，并拉低再拉高 PG14(RST) 复位 ESP8266
  • 你只需手动把 GPIO0 拉低（跳帽接 GND），配合自动复位，ESP8266 即进入下载模式
  • 全程共 7 步，涉及跳帽操作 2 次（第3步改 IO0 接 GND，第7步改回 3V3）
阶段一：准备透传桥程序
1 在 Keil 中切换参与编译的源文件

项目里有两套 main 函数和中断处理文件，必须排除原文件、包含 bridge 文件，否则编译会报"重复定义"错误。

操作 文件 路径
排除编译 main.c D:\modulebusLinkMQTT\User\main.c
包含编译 main_bridge.c D:\modulebusLinkMQTT\User\main_bridge.c
排除编译 stm32f1xx_it.c D:\modulebusLinkMQTT\User\stm32f1xx_it.c
包含编译 stm32f1xx_it_bridge.c D:\modulebusLinkMQTT\User\stm32f1xx_it_bridge.c
操作方法（Keil 中）：
1. 在左侧工程树中右键点击 main.c → 选择 Options for File 'main.c'
2. 在弹出窗口中取消勾选 "Include in Target Build" → 点击 OK
3. 右键 main_bridge.c → Options → 确认勾选 "Include in Target Build" → OK
4. 对 stm32f1xx_it.c 和 stm32f1xx_it_bridge.c 执行相同操作
替代方法（更简单）：直接在文件管理器中重命名
• main.c → main_backup.c
• main_bridge.c → main.c
• stm32f1xx_it.c → stm32f1xx_it_backup.c
• stm32f1xx_it_bridge.c → stm32f1xx_it.c
烧录完后恢复时，把名字换回来即可。
2 编译并下载透传桥程序到 STM32
  1. 按 F7（或 Project → Build Target）编译工程
  2. 确认编译 0 Error, 0 Warning
  3. 用 ST-Link 或 FlyMcu 把程序下载到 STM32
验证：下载成功后 LED1 常亮 = 桥接程序就绪
如果 LED1 不亮，检查是否下载成功、是否选错了文件

此时透传桥程序已运行，STM32 正在监听 USART1 和 USART3 的数据，准备双向转发。

阶段二：配置跳线，进入下载模式
3 配置所有跳帽（最关键一步！）

这是整个流程中唯一需要动跳帽的步骤。根据你板子的当前状态，大部分跳帽已经正确，只需要改 1 个。

跳帽编号 / 位置 烧录时应接 作用 需要操作
J85
(PB10 ↔ W_RX)		 插着 STM32 USART3_TX → ESP8266 RX 数据通道 不需要动
J84
(PB11 ↔ W_TX)		 插着 ESP8266 TX → STM32 USART3_RX 数据通道 不需要动
J66
(3V3 ↔ W_3V3)		 插着 给 ESP8266 供电 不需要动
EN ↔ 3V3
(蓝色跳帽)		 插着 使能 ESP8266 芯片 不需要动
IO0(GPIO0) ↔ GND
(黄色跳帽)		 改接 GND 拉低 GPIO0 = 进入下载模式 把跳帽从 3V3 拔下来，改插到 GND 侧
⚠️ 关键操作（唯一需要动的跳帽）：
找到 ESP8266 模块旁边的 IO0 跳帽（你之前照片里的黄色跳帽）。
如果它接在 IO0 ↔ 3V3 → 拔下来，改插到 IO0 ↔ GND
如果它已经接在 IO0 ↔ GND → 不用动，已经正确
为什么只改 GPIO0？
• J85/J84/J66 必须插着 — 这是 STM32 和 ESP8266 之间的数据通道，拔了就没法透传
• EN 跳帽插着 — 透传桥程序虽然会用 PG13 控制 EN，但物理跳帽接 3V3 更保险
• GPIO0 接 GND 是进入下载模式的必要条件 — 上电时 GPIO0 为低 = 下载模式，为高 = 正常启动
4 按开发板 RESET 键

按一下开发板上的 RESET 按键（红色小按键）。

按 RESET 后发生了什么：
1. STM32 复位，重新从头运行 main_bridge.c
2. 透传桥程序执行 macESP8266_CH_ENABLE() → PG13 拉高 → EN 使能
3. 透传桥程序执行 macESP8266_RST_LOW_LEVEL() → PG14 拉低 → 等 100ms
4. 透传桥程序执行 macESP8266_RST_HIGH_LEVEL() → PG14 拉高 → RST 释放
5. ESP8266 重新上电启动，检测到 GPIO0=低 → 进入下载模式
此时 ESP8266 已进入下载模式，正在等待烧录工具的连接信号。
阶段三：烧录固件与恢复
5 打开 Flash Download Tool，配置并烧录

第一步：运行工具，选择芯片类型

运行 flash_download_tool_x.x.x.exe 弹出窗口选择： ChipType : ESP8266 WorkMode : Develop LoadMode : UART → 点击 OK

第二步：主界面配置参数

参数 设置值 说明
COM 板载 CH340 的 COM 口 在设备管理器中查看，不是 USB-TTL 的口
BAUD 115200 如果不稳定降到 57600
SPI SPEED 40MHz 标准值
SPI MODE DIO ESP8266 标准模式
FLASH SIZE 8Mbit (1MB) 霸道 V2 板载 ESP8266 是 1MB Flash

第三步：加载固件文件

点击中间文件列表的空白行 → 浏览选择： D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin 地址栏填入： 0x00000 右下角勾选： ☑ DoNotChgBin （防止工具自动修改 bin 地址） 点击最下方： [ START ]
6 等待烧录完成

正常烧录过程：

SYNC → 工具与 ESP8266 握手成功 DOWNLOAD → 正在写入 Flash，进度条 0% → 100% FINISH → 绿色 = 烧录成功！
如果一直卡在 SYNC 不动：
1. 确认 IO0 跳帽接的是 GND（不是 3V3）
2. 确认 按了 RESET 键（在第4步）
3. 确认 COM 口选的是 板载 CH340 的口
4. 确认 J85/J84/J66 三个跳帽 都插着
5. 以上都对了 → 再按一次 RESET 键，重新点 START
7 恢复：改回跳帽 + 换回源文件

烧录成功后，需要恢复到正常工作状态。

① 改回 IO0 跳帽（必须！）

跳帽 烧录时 恢复后 操作
IO0(GPIO0) IO0 ↔ GND IO0 ↔ 3V3 拔下黄色跳帽，改插到 3V3 侧
J85/J84/J66 插着 插着 不动
EN ↔ 3V3 插着 插着 不动
⚠️ 如果不改回 IO0 跳帽，ESP8266 每次启动都会进入下载模式，MQTT 程序无法运行！

② 在 Keil 中恢复源文件

操作 文件
包含编译 main.c（恢复）
排除编译 main_bridge.c
包含编译 stm32f1xx_it.c（恢复）
排除编译 stm32f1xx_it_bridge.c

如果之前用的是重命名方法，把名字换回来即可。

③ 编译并下载 MQTT 应用程序到 STM32

  1. F7 编译
  2. ST-Link / FlyMcu 下载到 STM32
  3. 按 RESET 键
✅ 全部完成！ESP8266 已烧录 MQTT 固件，STM32 正在运行 MQTT 应用程序。
