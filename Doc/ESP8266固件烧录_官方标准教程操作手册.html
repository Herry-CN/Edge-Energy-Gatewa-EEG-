ESP8266 固件烧录 — 野火官方标准教程操作手册

核心思路（来自官方教程 PDF）：开发板板载的 ESP8266 通过 USB 转串口模块连接到电脑，ESP8266 能与电脑正常通讯，控制 IO0 脚接 GND 进入下载模式，烧录工具正确配置相关参数即可烧录固件。

关键区别：CH340 直接 对接 ESP8266，不经过 STM32 做数据转发。之前的桥接方案失败就是因为 STM32 转发引入延迟，导致 Flash Download Tool 上传 stub 和切换波特率时失败。

两种直连方法（选一种）

方法 A：板载 CH340 直连（官方教程原版）
方法 B：USB-TTL 直连（更简单，你已有硬件）

方法 A：板载 CH340 直连（完全按教程操作）

用板子自带的 CH340 芯片，拔掉 4 个跳帽，加 2 根杜邦线交叉连接。

适用场景：没有外部 USB-TTL 模块，或想完全按教程操作。

方法 B：USB-TTL 直连（推荐！你已有硬件）

用你买回来的 USB-TTL 小板，只需拔 2 个跳帽，接线你已经接好了一部分。

适用场景：已有 USB-TTL 模块（你已买好并接好线）。

原理完全一样：USB-TTL 本质就是一个独立的 CH340，和板载 CH340 功能相同，只是物理位置不同。

下面同时列出两种方法的每一步操作，你按自己选的方法执行即可。

第 1 步：拔跳帽

1方法 A（板载 CH340）：拔 4 个跳帽

跳帽位置原来连接操作目的
CH340 右侧（靠近 Mini USB）CH340 TXD ↔ PA9拔掉断开 CH340 与 STM32 USART1
CH340 右侧（靠近 Mini USB）CH340 RXD ↔ PA10拔掉断开 CH340 与 STM32 USART1
ESP8266 旁 J85PB10 ↔ W_RX拔掉断开 STM32 USART3 与 ESP8266
ESP8266 旁 J84PB11 ↔ W_TX拔掉断开 STM32 USART3 与 ESP8266
找 CH340 跳帽：CH340 芯片在板子 Mini USB 口旁边，右侧有 2 个跳帽将 CH340 的 TXD/RXD 连到 PA9/PA10。拔掉它们，CH340 的 TXD/RXD 就变成独立的排针，可以杜邦线引出。

1方法 B（USB-TTL）：只拔 2 个跳帽

跳帽原来连接操作目的
ESP8266 旁 J85PB10 ↔ W_RX拔掉断开 STM32 USART3_TX，避免和 USB-TTL TXD 抢 W_RX
ESP8266 旁 J84PB11 ↔ W_TX拔掉断开 STM32 USART3_RX，避免和 USB-TTL RXD 抢 W_TX
方法 B 不需要动 CH340 跳帽：因为你用的是外部 USB-TTL，板载 CH340 留着给 STM32 用也不影响——数据走 USB-TTL 的独立 COM 口。

第 2 步：杜邦线交叉连接

2方法 A（板载 CH340）：2 根杜邦线

CH340 排针端ESP8266 排针端注意
CH340 TXDESP8266 W_RX（URX）交叉！TX 对 RX
CH340 RXDESP8266 W_TX（UTX）交叉！RX 对 TX
千万注意：TX→RX、RX→TX 交叉连接，不是 TX→TX！接反了 Flash Download Tool 会一直卡在 SYNC 不动。

2方法 B（USB-TTL）：你之前已经接好了，确认即可

USB-TTL 端颜色开发板端状态
TXD棕色W_RX已接好
RXD黑色W_TX已接好
GND白色板子 GND已接好
3V3红色不接（悬空）正确
确认：USB-TTL 跳帽在 3.3V 位置（之前已改好）。ESP8266 由开发板供电，USB-TTL 只负责数据线。

第 3 步：EN 接 3V3，IO0 接 GND

3两种方法都一样，确认跳帽状态

跳帽/拨钮应接位置你的当前状态操作
EN ↔ 3V33V3已接好不动
IO0 ↔ GNDGND已接好不动
J66 3V3↔W_3V3插着已接好不动
原理：ESP8266 芯片启动时，若 IO0 为低电平，芯片会进入下载模式。EN 接 3V3 保证芯片正常使能。

第 4 步：74880 波特率验证下载模式（★ 教程关键步骤！）

4打开串口调试助手，验证 ESP8266 是否进入下载模式

  1. 打开串口调试助手（野火多功能调试助手 / SSCOM / 串口大师 都行）
  2. 选择 COM 口：
    • 方法 A：选板载 CH340 的 COM 口（如 COM4）
    • 方法 B：选 USB-TTL 的 COM 口（看设备管理器，可能是 COM5 或其他）
  3. 波特率设为 74880（不是 115200！74880 是 ESP8266 ROM 启动信息的固定波特率）
  4. 数据位 8，停止位 1，无校验
  5. 点击"打开串口"
  6. 按一下开发板的 RESET 键（让 ESP8266 重新启动）

成功标志：串口助手收到类似以下信息：

ets Jan 8 2013,rst cause:1, boot mode:(3,6) load 0x40100000, len 1396, room 16

看到 boot mode:(3,x) 或 boot mode:(1,x) = ESP8266 已进入下载模式，可以继续烧录。

如果 ESP8266 一直闪灯、反复复位、重复打印信息：

说明 RST 脚悬空不稳定。将 RST 脚接 3V3 即可解决。

霸道 V2 上 RST 由 STM32 的 PG14 控制。如果 STM32 没跑初始化程序，PG14 悬空会导致 RST 不稳定。解决方法：

  • 方案 1：让 STM32 跑任意带 ESP8266_Init() 的程序（如之前的透传桥 main_bridge.c），按 RESET 后 STM32 会自动拉高 RST
  • 方案 2：找到 ESP8266 模块上方的 RST 排针，用杜邦线接 3V3

如果什么都没收到（空白）：

  • 检查 TX/RX 是否接反（TX→RX 交叉，不是 TX→TX）
  • 检查 GND 是否接好
  • 检查 COM 口是否选对
  • 检查 IO0 是否真的接了 GND

第 5 步：关闭串口助手，打开 Flash Download Tool

5关闭串口助手（释放 COM 口）

必须关闭！串口助手和 Flash Download Tool 不能同时占用同一个 COM 口，否则烧录失败。

5b打开 Flash Download Tool

  1. 运行 flash_download_tool_x.x.x.exe
  2. 弹窗选择：
    • ChipType：ESP8266
    • WorkMode：Develop
    • LoadMode：UART
  3. 点击 OK

第 6 步：Flash Download Tool 配置参数

第 7 步：按 RESET 后点 START

7重要顺序：先按 RESET，再点 START

  1. 按一下开发板的 RESET 键 — 让 ESP8266 重新进入下载模式
  2. 点击 Flash Download Tool 的 START 按钮

正常流程：

IDLE 等待 → SYNC → DOWNLOAD → FINISH（绿色）

进度条从 0% 走到 100%，绿色 FINISH 出现 = 烧录成功。

第 8 步：烧录完成后验证

8恢复 IO0 到 3V3，验证 AT 命令

  1. 把 IO0 跳帽/拨钮从 GND 改回 3V3（不改回 ESP8266 会一直停在下载模式！）
  2. 按一下开发板 RESET 键
  3. 打开串口调试助手，COM 口不变
  4. 波特率改为 115200（不是 74880 了）
  5. 发送 AT（后面要加回车换行！）

成功标志：收到 OK 回复 = 固件烧录正常，通信正常。

也可以发送 AT+GMR 查看版本信息：

发送 AT+GMR，应返回固件版本号、SDK 版本、编译时间等信息。

第 9 步：恢复跳帽和程序

9把所有跳帽恢复到正常工作位置

跳帽烧录时恢复后
J85 PB10↔W_RX拔掉插回
J84 PB11↔W_TX拔掉插回
J66 3V3↔W_3V3插着不动
CH340 TXD↔PA9（方法A）拔掉插回
CH340 RXD↔PA10（方法A）拔掉插回
EN↔3V33V3不动
IO0↔3V3GND改回3V3

9bKeil 恢复源文件

  1. main.c → 勾选 "Include in Target Build"
  2. stm32f1xx_it.c → 勾选 "Include in Target Build"
  3. main_bridge.c → 取消勾选
  4. stm32f1xx_it_bridge.c → 取消勾选
  5. F7 编译 → 下载到 STM32

现在 MQTT 应用程序就可以正常运行了。

烧录失败排查（来自官方教程）

现象原因解决
卡在 SYNC 不动ESP8266 没进下载模式确认 IO0 接 GND → 按 RESET → 再 START
卡在"等待上电过程"接线无误但 ESP8266 没复位将 RST 引脚接地复位一下
COM 口错误/被占用串口助手没关关闭所有占用 COM 口的软件
电源不稳定USB 供电不足换 USB 口或用独立电源
ESP8266 反复复位RST 脚悬空将 RST 脚接 3V3
波特率过高失败线太长/质量差降低波特率到 57600 或更低
固件超过 Flash 大小1MB Flash 烧了 2MB 固件确认用 1MB 版本固件
串口芯片选型不对用了 RS232/485必须用 TTL 电平（CH340/CP2102）
