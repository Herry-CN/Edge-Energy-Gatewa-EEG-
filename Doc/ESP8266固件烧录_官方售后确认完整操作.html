ESP8266 MQTT 固件烧录完整操作手册

适用板卡：野火 STM32F103 霸道 V2 开发板（板载 ESP8266-12F，1MB Flash）
固件目标：ESP8266 MQTT-AT 固件（项目已自带 Doc/ESP8266_AT_MQTT_1M.bin）
核心思路：官方售后确认 EN 接 3.3V、IO0 接 GND、用 CH340 串口烧录。本手册补全被省略的关键步骤：STM32 必须先运行透传桥程序，把板载 CH340（USART1）转发到 ESP8266（USART3）。

重要前提：板载 CH340 连接的是 STM32 的 USART1（PA9/PA10），不是直接连 ESP8266。ESP8266 接在 STM32 的 USART3（PB10/PB11）上。因此烧录前必须给 STM32 下载透传桥程序，否则 CH340 与 ESP8266 根本不通。

二、第一阶段：给 STM32 下载透传桥程序

1
打开 Keil 工程
双击 D:\modulebusLinkMQTT\Project\Fire_F103ZE.uvprojx。左侧工程树展开 USER 分组。
2
确保桥程序已加入工程
若 USER 分组里没有 main_bridge.c 和 stm32f1xx_it_bridge.c：
  • 右键 USER → Add Existing Files to Group 'USER'
  • 选中 main_bridge.c 和 stm32f1xx_it_bridge.c → Add
3
切换参与编译的文件
右键文件 → Options for File 'xxx' → 勾选/取消 Include in Target Build：
文件状态
main.c❌ 取消勾选
main_bridge.c✅ 勾选
stm32f1xx_it.c❌ 取消勾选
stm32f1xx_it_bridge.c✅ 勾选
两个 main 函数和两个 USART1_IRQHandler 不能同时编译，否则会报错。
4
编译并下载
按 F7 编译，应显示 0 Error(s)（警告可忽略）。
用 ST-Link 或 FlyMcu 下载到 STM32。
5
确认桥接就绪
下载完成后看板载 LED：
  • LED1 常亮 = 透传桥初始化完成
  • LED2 闪烁 = 主循环运行正常

三、第二阶段：配置 ESP8266 进入下载模式

官方售后原话："en 接 3.3，io0 接 gnd，8266 使能脚上电后，串口去接 CH340 就行"。以下是按此思路的具体跳线配置。
跳线/拨钮正常位置烧录时应接说明
J85（PB10 ↔ W_RX）插着✅ 插着STM32 USART3 接收 ESP8266 数据
J84（PB11 ↔ W_TX）插着✅ 插着STM32 USART3 发送给 ESP8266
J66（3V3 ↔ W_3V3）插着✅ 插着ESP8266 供电
EN（CH_PD）↔ 3V3插着✅ 插着ESP8266 使能，必须接 3.3V
IO0 / GPIO0 ↔ 3V3插着⚠️ 改接 GND拉低进入下载模式
6
改接 IO0 到 GND
把 ESP8266 模块旁的 IO0 拨钮/跳帽从 3V3 改拨到 GND。
7
按 RESET 复位 STM32
按一下开发板红色 RESET 键。STM32 透传桥程序会重新初始化，并自动完成 ESP8266 的复位时序（EN 拉高 → RST 拉低 100ms → RST 拉高）。此时 IO0 已接地，ESP8266 进入下载模式。

四、第三阶段：烧录 ESP8266 固件

不要用乐鑫 Flash Download Tool！ 该工具会先上传 stub 并把波特率切换到 230400/460800，STM32 透传桥无法跟随切换，会报 esp_stub_and_set_baud 错误。必须使用 esptool.py --no-stub 在固定 115200 下烧录。
8
关闭所有串口软件
关闭野火调试助手、Flash Download Tool、串口助手等任何占用 COM4 的程序。
9
打开 PowerShell 执行 esptool.py
复制下面整条命令粘贴执行（每行末尾的 ` 是 PowerShell 换行符，必须保留）： 
C:\Users\admin\.workbuddy\binaries\python\envs\pdfenv\Scripts\python.exe -m esptool `
  --chip esp8266 `
  --port COM4 `
  --baud 115200 `
  --no-stub `
  write_flash `
  --flash_mode dio `
  --flash_freq 40m `
  --flash_size 1MB `
  0x00000 `
  "D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin"
注：COM 口号以设备管理器中板载 CH340 的实际端口为准，通常是 COM4。
10
等待烧录完成
正常输出会显示： 
Connecting....
Chip is ESP8266EX
Changing baud rate to 115200
Configuring flash size...
Flash params set to 0x0220
Compressed 1048576 bytes to ...
Wrote 1048576 bytes (...)
Verifying...
Hash of data verified.
Leaving...
Hard resetting via RTS pin...
Failed to connect to ESP8266: No serial data received in bootloader. (this is normal after --no-stub)
最后一句是 --no-stub 模式的正常现象，表示烧录已经成功。

五、第四阶段：恢复正常运行

11
把 IO0 接回 3V3
烧录成功后，必须将 IO0 拨钮从 GND 拨回 3V3。否则 ESP8266 每次上电都会进入下载模式，无法正常启动。
12
恢复 STM32 主程序
回到 Keil，把编译目标切换回来：

stm32f1xx_it_bridge.c❌ 取消勾选
按 F7 编译，重新下载到 STM32。
13
验证 MQTT-AT 固件
打开野火多功能调试助手：
  • 端口：COM4
  • 波特率：115200
  • 数据位 8、停止位 1、无校验
  • 勾选发送新行
按 RESET 后发送：

应返回：

发送： 
AT+GMR
应返回版本号。

六、常见问题排查

现象原因解决
esptool 提示 Failed to connect to ESP8266: No serial data received in bootloader. ESP8266 没进下载模式 确认 EN 接 3V3、IO0 接 GND、已按 RESET；关闭其他串口软件重试
Flash Download Tool 报 esp_stub_and_set_baud 工具上传 stub 后切换波特率，透传桥跟不上 改用 esptool.py --no-stub
调试助手收到乱码 IO0 还接在 GND，ESP8266 停在下载模式 IO0 拨回 3V3 并复位
发 AT 无返回 STM32 还跑着透传桥，或主程序未恢复 确认 Keil 已恢复 main.c/it.c 并重新下载
LED1 不亮 桥程序未下载成功 重新编译下载 main_bridge.c

七、核心要点回顾

  1. 必须先给 STM32 下载透传桥（官方售后省略的关键步骤）
  2. EN 接 3.3V、IO0 接 GND，按 RESET 进入下载模式
  3. 用 esptool.py --no-stub 烧录，不能用 Flash Download Tool
  4. 烧录完一定要把 IO0 接回 3.3V
  5. 恢复 main.c/it.c 后重新下载 STM32
