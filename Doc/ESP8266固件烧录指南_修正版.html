帖子用户反馈的高频问题

  • "烧完不断重启" → 固件尺寸不对或 IO0 没接回 3V3
  • SYNC 卡住 → 帖子建议把 RST 脚接 3V3 再接 GND 做一次手动复位

🚀 方案A 详细操作（7 步）

i
准备：Flash Download Tool（乐鑫官网下载） + 固件 Doc/ESP8266_AT_MQTT_1M.bin（1024KB = 1MB 整） + USB-TTL 小板 + 杜邦线 5 根
1

断电，拔 USART3 跳帽

板子断电。找到 ESP8266 旁边的跳帽区，拔掉 2 个跳帽：

正常工作状态： PB10 ─[跳帽]─ W_RX ← 拔掉 PB11 ─[跳帽]─ W_TX ← 拔掉 3V3 ─[跳帽]─ W_3V3 ← 保留！ESP8266 供电
!
W_3V3 跳帽绝对不能拔！ESP8266 靠这个跳帽从板子获取 3.3V 电源。
2

接 USB-TTL 数据线（3 根杜邦线）

将 USB-TTL 的 TX/RX/GND 接到拔掉跳帽后暴露的 ESP8266 侧引脚：

USB-TTL 小板 板子（ESP8266 侧跳帽座） TX ──杜邦线──> W_RX (原 PB10 跳帽座，找标 W_RX 的那排) RX ──杜邦线──< W_TX (原 PB11 跳帽座，找标 W_TX 的那排) GND ──杜邦线──> 任意 GND 引脚
!!
关键：TX→RX，RX→TX，交叉连接！接反了 Flash Download Tool 会一直 SYNC 不动（论坛帖子多人踩坑）。
i
USB-TTL 的 VCC 不需要接——ESP8266 由板子 W_3V3 跳帽供电。只接 TX、RX、GND 三根线。
3

进下载模式：IO0 拉低 + EN 拉高

找到 ESP8266 旁边的 IO 跳帽（正常接 3V3），以及 EN(CH_PD) 引脚：

IO 跳帽（有物理跳帽）： 正常状态： IO ─[跳帽]─ 3V3 ← 拔掉跳帽 下载模式： IO ─[杜邦线]─ GND ← 改接 GND EN / CH_PD 引脚（接在 PG13 上，无物理跳帽）： ← 用杜邦线将 EN 引脚接到 3V3 (从 ESP8264 上方的 4 个编程引脚中找到 EN，接 3V3)
[勘误] 原文写"EN 跳帽接在 3V3，正常位置不用动" EN 跳帽 → EN 接 PG13 由 STM32 控制，烧录时必须用杜邦线物理接 3V3
!!
为什么 EN 必须物理接 3V3？因为 CH_PD(EN) 接在 STM32 的 PG13 上。 烧录时 STM32 可能没运行 ESP8266_Init()，PG13 状态不确定（可能为低）， ESP8266 会被禁用。必须用杜邦线强制 EN=3V3。
4

手动复位 ESP8266（关键！）

IO0 已接 GND、EN 已接 3V3 后，需要让 ESP8266 做一次复位才能进入下载模式：

ESP8266 的 RST 在 PG14 上，板子 RST 按钮只复位 STM32，不一定能复位 ESP8266。 正确做法：找到 ESP8266 的 RST 引脚（4 个编程引脚之一） ① 先将 RST 引脚碰一下 GND（拉低复位） ② 然后接回 3V3（释放复位） ③ 此时 ESP8266 以 IO0=LOW 重启 → 进入下载模式
[勘误] 原文写"按一下板子复位键（RST），ESP8266 就进入下载模式" 按板子 RST 键 → 手动碰 RST 引脚 GND→3V3（PG14 由 STM32 控制，板子 RST 按钮不直接复位 ESP8266）
!
如果手边找不到 RST 引脚，也可以直接拔一下 ESP8266 的 W_3V3 跳帽再插回去（断电再上电），效果等同于复位。但要确保 IO0 已经接 GND。
5

连接 USB，确认 COM 口

板子 USB 线接电脑（供电） + USB-TTL 小板 USB 线接电脑（数据）。

打开 Windows 设备管理器 → 端口（COM 和 LPT），记住 USB-TTL 的 COM 口号。

!
板载 CH340 也会显示一个 COM 口，不要选这个。选 USB-TTL 小板对应的 COM 口。
6

Flash Download Tool 烧录

运行 flash_download_tool_x.x.x.exe，弹框选 ESP8266 / Develop / UART → OK

参数设置值
COMUSB-TTL 的 COM 口（不是板载 CH340）
BAUD115200
SPI SPEED40MHz
SPI MODEDIO
FLASH SIZE8Mbit（1MB）
固件路径D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin
烧录地址0x00000
DoNotChgBin勾选

点 START → 进度条 SYNC → DOWNLOAD → FINISH（绿色） = 成功

7

恢复运行状态

按顺序恢复： ① 拔掉 USB-TTL 的 3 根数据线 + EN/RST 杜邦线 ② IO 跳帽接回 3V3（← 不接回 ESP8266 不启动！） ③ PB10↔W_RX、PB11↔W_TX 两个跳帽插回原位 ④ 按复位键 ⑤ ESP8266 上电正常启动，蓝灯闪烁 = 正常工作

🔧 常见问题排查

一直停在 SYNC，不动
最常见原因。依次检查：
① IO 引脚是否接 GND（不是 3V3）
② EN 引脚是否物理接 3V3（不能靠 STM32）
③ RST 是否做过 GND→3V3 复位动作（不能只按板子 RST）
④ TX/RX 是否交叉（TX→RX，RX→TX，不是 TX→TX）
⑤ 杜邦线是否接触良好（论坛多人反馈是接触问题）
下载到一半失败
把 BAUD 从 115200 降到 57600 或 38400 重试。杜邦线太长也会导致信号不稳。
FINISH 了但 ESP8266 不断重启
① IO 跳帽是否已接回 3V3（没接回会一直进下载模式循环）
② 固件尺寸是否正确（必须用 1MB 版本，文件大小 1,048,576 字节）
③ SPI MODE 是否设为 DIO（不是 QIO）
设备管理器看不到 USB-TTL 的 COM 口
缺少驱动。CH340 搜"CH340 驱动"，CP2102 搜"CP2102 驱动"，PL2303 搜"PL2303 驱动"。

✅ 固件验证（修正版）

!
重要纠正：刷写完成后，不要用板载 CH340 的 COM 口直接看 ESP8266 响应—— 因为 USART3 跳帽恢复后 ESP8266 在 USART3(PB10/PB11) 上，CH340 在 USART1(PA9/PA10) 上，两者不是同一条串口。

正确的验证方法：用 USB-TTL 直连 ESP8266

保持 USART3 跳帽拔掉，USB-TTL 仍接 W_RX/W_TX 1. 打开串口助手，选 USB-TTL 的 COM 口 2. 波特率 115200，N-8-1 3. 先给 ESP8266 做一次复位（RST 碰 GND 再接 3V3） 4. 串口应返回： ready （注意：全新刷写后 WiFi 配置已被擦除， 不会出现 WIFI CONNECTED / WIFI GOT IP） 5. 发送 AT\r\n → 应返回 OK 6. 发送 AT+GMR\r\n → 返回版本信息 （查看版本字符串中是否包含 MQTT 相关信息） 7. 发送 AT+MQTTUSERCFG=0,1,"","test","","",0,0,""\r\n → 如果返回 OK 而非 ERROR，说明 MQTT 指令集已加载
[勘误] 原文验证部分：
"串口应返回 ready / WIFI CONNECTED / WIFI GOT IP" → 只返回 ready（全新刷写 WiFi 配置被擦除）
"选板载 CH340 的 COM 口" → 选 USB-TTL 的 COM 口（CH340 在 USART1，ESP8266 在 USART3）
"AT+MQTTUSERCFG? 查询" → AT+GMR 看版本 + AT+MQTTUSERCFG=... 实测是否被识别
