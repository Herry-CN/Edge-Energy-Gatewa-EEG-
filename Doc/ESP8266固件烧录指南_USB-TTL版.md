# ESP8266 固件烧录操作指南（USB-TTL 版）

> 更新日期：2026-08-10
> 硬件：野火 STM32F103 霸道 V2 开发板（板载 ESP8266-12F，1MB Flash）
> 固件：`Doc/ESP8266_AT_MQTT_1M.bin`（项目自带，支持 MQTT AT 指令）

---

## 一、论坛链接分析

你给的链接 https://www.firebbs.cn/forum.php?mod=viewthread&tid=15750 是**野火官方的 ESP8266 烧录教程**，由火哥本人发布。关键发现：

1. **硬件规格书第 21 页直接引用了这个帖子**——原文写的是"ESP8266 正上方的四个引脚可用来更新 WIFI 固件，具体操作参照[此帖子]"。所以这是**官方钦定方法**。

2. 帖子的核心思路是**用板载 CH340 芯片给 ESP8266 刷固件**：拔掉 USART1 和 USART3 的跳帽，用 2 根杜邦线把 CH340 的 TX/RX 交叉接到 ESP8266 的 RX/TX 上，然后 IO0 接 GND 进下载模式。

3. 帖子中多个用户反馈的"SYNC 卡住"问题，根因都是**TX/RX 接反**或**接触不良**——交叉接线是关键（CH340_TX → ESP8266_RX，CH340_RX → ESP8266_TX）。

**结论：论坛帖子的方法完全有效，它就是我们说的"方案C"。你现在有 USB-TTL，可以用更简单的"方案A"。**

---

## 二、方案选择

| 对比项 | 方案A：USB-TTL 直连 | 方案B：STM32 透传桥 | 方案C：野火官方跳帽法 |
|--------|-------------------|-------------------|---------------------|
| 额外硬件 | USB-TTL 小板（已购买） | 无 | 2 根杜邦线 |
| USB 线数量 | 2 根（板子供电 + USB-TTL） | 1 根 | 1 根 |
| 需改代码 | 不需要 | 需要（替换 main.c） | 不需要 |
| 拔跳帽数量 | 2 个（USART3） | 0 个 | 4 个（USART1+USART3） |
| 串口独立性 | 独立 COM 口，零干扰 | 经 STM32 转发 | 板载 CH340 直连 |
| 操作步数 | 6 步 | 5 步 | 7 步 |
| 推荐度 | ★★★★★ | ★★★ | ★★★★ |

### 推荐：方案A（USB-TTL 直连）

你既然已经买了 USB-TTL，这是最方便的方案：
- **不需要改任何代码**——不碰 STM32 程序
- **独立串口**——完全不经过 STM32，零干扰风险
- **只拔 2 个跳帽**——不动 USART1
- 以后每次刷固件都省事

## 三、方案A 详细操作步骤（6 步）

### 准备工作

- 工具：Flash Download Tool（乐鑫官网下载）
- 固件：`D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin`（已有，精确 1,048,576 字节 = 1024KB = 1MB）
- 硬件：USB-TTL 小板（CH340/CP2102/PL2303 均可）、杜邦线若干、板子 USB 供电

### Step 1：断电，拔 USART3 跳帽

板子断电。找到 ESP8266 旁边的 3 组跳帽：

```
正常工作状态（跳帽位置）：
  PB10  ─[跳帽]─ W_RX    ← 拔掉这个
  PB11  ─[跳帽]─ W_TX    ← 拔掉这个
  3V3   ─[跳帽]─ W_3V3   ← 保留（给 ESP8266 供电）
```

拔掉 PB10↔W_RX 和 PB11↔W_TX 两个跳帽。这样 STM32 的 USART3 就和 ESP8266 断开了，ESP8266 的 RX/TX 引脚暴露在跳帽座上。

> **注意**：W_3V3 跳帽不要拔！ESP8266 需要板子供电。

### Step 2：接 USB-TTL 线（3 根杜邦线）

```
USB-TTL 小板          板子跳帽座（ESP8266 侧）
  TX   ──杜邦线──>   W_RX   (原 PB10 跳帽座，ESP8266 侧那排)
  RX   ──杜邦线──<   W_TX   (原 PB11 跳帽座，ESP8266 侧那排)
  GND  ──杜邦线──>   任意 GND 引脚
```

**关键：TX→RX，RX→TX，交叉连接！** 接反了会一直 SYNC 不动。

> USB-TTL 的 VCC **不需要接**——ESP8266 由板子供电。只接 TX、RX、GND 三根线。

### Step 3：进下载模式（IO0 拉低）

找到 ESP8266 旁边的 IO 跳帽（正常接 3V3）：

```
正常状态：  IO ─[跳帽]─ 3V3    ← 拔掉跳帽
下载模式：  IO ─[杜邦线]─ GND  ← 改接 GND
```

同时确认 **EN(CH_PD) 引脚用杜邦线接到 3V3**——EN 接在 STM32 的 PG13 上由固件控制，不是物理跳帽，烧录时 STM32 可能没运行 ESP8266_Init()，PG13 状态不确定，必须物理接 3V3 确保 ESP8266 使能。

接好后**手动复位 ESP8266**：将 RST 引脚（PG14，也由 STM32 控制）碰一下 GND 再接回 3V3。板子 RST 按钮只复位 STM32，不一定能复位 ESP8266。

> **如果找不到 RST 引脚**，可以拔一下 W_3V3 跳帽再插回去（断电再上电），效果等同于复位。但要确保 IO0 已经接 GND。

### Step 4：连接 USB，确认 COM 口

1. 板子 USB 线接电脑（供电）
2. USB-TTL 小板 USB 线接电脑
3. 打开 Windows 设备管理器 → 端口（COM 和 LPT）
4. 记住 USB-TTL 的 COM 口号（比如 COM5）
   - 板载 CH340 也会显示一个 COM 口（比如 COM3），**不要选这个**

### Step 5：打开 Flash Download Tool 烧录

1. 运行 `flash_download_tool_x.x.x.exe`
2. 弹框选择：
   - ChipType：**ESP8266**
   - WorkMode：**Develop**
   - LoadMode：**UART**
   - 点 OK

3. 主界面 SPI Download 标签页配置：

   | 参数 | 设置值 |
   |------|--------|
   | COM | **选 USB-TTL 的 COM 口**（不是板载 CH340 的） |
   | BAUD | **115200** |
   | SPI SPEED | **40MHz** |
   | SPI MODE | **DIO** |
   | FLASH SIZE | **8Mbit（1MB）** |

4. 文件加载：
   - 勾选第一行
   - 点浏览选 `D:\modulebusLinkMQTT\Doc\ESP8266_AT_MQTT_1M.bin`
   - 地址写 **0x00000**
   - 勾选 **DoNotChgBin**

5. 点 **START** 按钮

6. 等待进度条走完：
   - SYNC → DOWNLOAD → **FINISH**（绿色）= 成功

### Step 6：恢复运行状态

1. 拔掉 USB-TTL 的 3 根杜邦线
2. **IO 跳帽接回 3V3**（← 重要！不接回 ESP8266 不启动）
3. 把 PB10↔W_RX、PB11↔W_TX 两个跳帽插回原位
4. 按复位键
5. ESP8266 上电正常启动，蓝灯闪烁 = 正常工作

## 四、常见问题排查

### 问题1：一直停在 SYNC，不动

**原因**：ESP8266 没进下载模式，或 TX/RX 接反。

**解决**：
1. 确认 IO 跳帽接的是 GND 不是 3V3
2. 确认 EN 引脚用杜邦线物理接了 3V3（不是靠 STM32 的 PG13）
3. 确认做了 RST 手动复位（GND→3V3），不是只按板子 RST 按钮
4. 确认 TX→RX、RX→TX 交叉（不是 TX→TX）
5. 如果以上都对，把杜邦线拔了重插，确保接触良好（论坛帖子多人反馈是接触问题）
6. 如果还不行，拔一下 W_3V3 跳帽再插回去（断电重上电，等效复位）

### 问题2：下载到一半失败

**原因**：波特率太高或线太长。

**解决**：把 BAUD 从 115200 降到 57600 或 38400 重试。

### 问题3：FINISH 了但 ESP8266 不工作（不断重启）

**原因**：刷了错误尺寸的固件，或 IO0 没接回 3V3。

**解决**：
1. 确认 IO 跳帽已接回 3V3
2. 确认用的是 `ESP8266_AT_MQTT_1M.bin`（1MB 版本，不是 2MB/4MB 版本）
3. 重新刷一次

### 问题4：设备管理器看不到 USB-TTL 的 COM 口

**原因**：缺少驱动。

**解决**：
- CH340 芯片：搜"CH340 驱动"安装
- CP2102 芯片：搜"CP2102 驱动"安装
- PL2303 芯片：搜"PL2303 驱动"安装

## 五、如果不想用 USB-TTL：方案C（论坛方法）速查

万一 USB-TTL 有问题，论坛方法也能用，不需要额外硬件：

1. 拔 4 个跳帽：USART1 的 PA9↔CH_RX、PA10↔CH_TX，USART3 的 PB10↔W_RX、PB11↔W_TX
2. 用 2 根杜邦线交叉连接：
   - CH340 的 RXD → ESP8266 的 W_TX（UTX）
   - CH340 的 TXD → ESP8266 的 W_RX（URX）
3. IO 跳帽接 GND，EN 跳帽接 3V3
4. 板子 USB 线接电脑
5. Flash Download Tool 选**板载 CH340 的 COM 口**，其余参数同方案A
6. START → FINISH
7. 恢复：拔杜邦线，4 个跳帽插回，IO 接回 3V3

## 六、固件验证

烧录完成后，用 USB-TTL 直连 ESP8266 验证（不要用板载 CH340——USART3 跳帽恢复后 ESP8266 在 USART3 上，CH340 在 USART1 上，两者不是同一条串口）：

1. 保持 USART3 跳帽拔掉，USB-TTL 仍接 W_RX/W_TX
2. 打开串口助手，选 **USB-TTL 的 COM 口**
3. 波特率 115200，N-8-1
4. 复位 ESP8266（RST 碰 GND 再接 3V3），串口应返回：
   ```
   ready
   ```
   > 注意：全新刷写后 WiFi 配置被擦除，不会出现 WIFI CONNECTED / WIFI GOT IP
5. 发送 `AT\r\n` 应返回 `OK`
6. 发送 `AT+GMR\r\n` 查看版本信息，确认固件类型
7. 发送 `AT+MQTTUSERCFG=0,1,"","test","","",0,0,""\r\n`，返回 OK 说明 MQTT 指令集已加载

如果以上都正常，说明固件烧录成功，可以下载 MQTT 主程序到 STM32 开始使用了。
